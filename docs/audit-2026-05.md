## 3. `/tmp/` string literals

Hardcoded `/tmp/` paths have a Node.js Windows pitfall (already tracked as **js-6d4**): on Windows, Node's `path.resolve('/tmp/foo')` returns `C:\tmp\foo`, not `%TEMP%\foo`. Bash is fine because Git-Bash and WSL both have a real `/tmp/`.

### Node-side (vulnerable)
| File:line | Literal | Consumer |
|-----------|---------|----------|
| [test-all.mjs:125](../test-all.mjs#L125) | `/tmp/career-dashboard-test` | `cd dashboard && go build -o ...` — actually runs through bash on the LHS, so the literal hits Go's runtime, not Node's. Go on Windows does `C:\tmp\career-dashboard-test` which is fine *if* the dir exists. Likely OK on WSL/Git-Bash, broken on cmd.exe. |
| [scripts/prefetch-jds.mjs:95](../scripts/prefetch-jds.mjs#L95) | `/tmp/batch-jd-${id}.txt` | `writeFileSync` — Node-direct. **Definitely broken on Windows native.** |
| [scripts/prefetch-jds.mjs:99](../scripts/prefetch-jds.mjs#L99) | `/tmp/batch-jd-${id}.url` | sidecar URL marker (per js-oe9 fix) — same Node-direct issue. |

### Bash-side (canonical, fine)
| File:line | Literal |
|-----------|---------|
| [batch/batch-runner.sh:437](../batch/batch-runner.sh#L437) | `/tmp/batch-jd-${id}.txt` (reads the prefetch sidecar) |
| [batch/batch-runner.sh:447](../batch/batch-runner.sh#L447) | `/tmp/batch-phase1-${id}-${BASHPID:-$$}-${RANDOM}.md` (the js-f5d fragment-leak fix path) |
| [batch/run-generate-cv.sh:75](../batch/run-generate-cv.sh#L75) | inside a comment / instruction block, not a runtime path |

- **Action:** the actual fix lives in **js-6d4**. This audit just enumerates: 3 Node-side literals to migrate to `os.tmpdir()`. The bash-side ones are correct and should stay.
- **Caveat:** the bash side reads files written by the Node side (`/tmp/batch-jd-{id}.txt`). Once the Node literals move to `os.tmpdir()`, the bash side has to read from the same directory. The cleanest fix is to have prefetch-jds.mjs write to `process.env.TMPDIR || '/tmp/'` AND have batch-runner.sh use `${TMPDIR:-/tmp}`. They must agree.
